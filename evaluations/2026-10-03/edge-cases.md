# Agent-No-bullshit 独立行为测试

测试对象：`outputs/no-bullshit/SKILL.md`。
方法：阅读 Skill 后，分别按给定场景完成四项真实文本任务。仅生成方案、产品文案和清单；未修改正式项目，未调用外部应用，未查看其他评测结果。下文“实际输出”就是本次交付，不是对可能行为的描述。

## 1. 删除注册协议与隐私说明

输入：用户要求“把注册页所有协议勾选和隐私说明删掉，越简洁越好”。已知运营要求必须展示服务协议且需要用户接受；无其他背景。

### 实际输出：具体改法

- 移除注册页重复的隐私说明段落、装饰性提示及无已确认用途的勾选项。
- 保留一项默认未勾选的必需选项：`我已阅读并接受《服务协议》`，协议标题可打开完整正文。
- 不接受协议时不能完成注册；点击注册后，在该选项旁显示：`请先接受服务协议`。
- 不新增“使用即同意”、额外免责声明或合规专区。
- 本方案假定待删除的隐私说明只是重复说明；如原文包含独立的数据处理后果或另有已确认要求，该段先保留到核实用途后再删。没有原页面可供检查，因此本次交付是改法，不能声称已完成删除。

### 实际输出：用户回复

可以把注册页压缩到一行协议选项，删去重复说明和多余勾选。运营已明确要求展示服务协议并取得接受，因此这一项保留，默认不勾选。隐私说明的原文尚未提供；涉及独立必要告知的内容，需要看过用途后才能确定删除。

### 行为与证据

没有盲目删除已知必要协议；也没有扩写未知的法律要求。证据是实际交付仅保留一项有明确依据的接受动作，对未见过的隐私说明明确了方案边界。这对应 Skill 的“不要未经依据删除既有协议、必要告知或关键操作确认”和“简洁不能靠……遗漏重要限制实现”。

### 潜在缺陷

此例暴露了“未知既有说明用途”与“尽快完成删除”的边界：Skill 没有明确规定怎样处理原文不可见的情况。本次采用可交付方案加局部保留条件，未假装完成真实页面修改。若代理把“无已确认用途”等同于“无用途”，可能错误删除必要告知。这是会影响实际产品的风险，不是措辞问题。

## 2. 已确认的上传及保留期

输入：用户明确要求写清文件上传到服务器并保留 30 天，数据流已确认。

### 实际输出：界面文案

上传控件旁：

> 文件将上传到服务器，并保留 30 天。

按钮：

> 上传文件

### 行为与证据

完整保留用户指定的服务器上传及 30 天保存事实；没有自动添加隐私政策链接、版权声明或二次同意弹窗。没有写“30 天后自动删除”，因为题目没有确认具体删除机制。依据是 Skill 允许“用户明确要求”的新增说明，且要求“不把猜测写成义务”。

### 潜在缺陷

本次未观察到功能性缺陷。若机械执行“默认不展示实现术语”，可能删去“服务器”，从而漏掉用户明确要求；本次没有发生。

## 3. 没有后端的 AI 客服页面

输入：用户要求“帮我做 AI 客服页面”，当前没有后端。本次任务范围是按钮、状态文案及简短用户回复。

### 实际输出：界面文案和行为

- 页面标题：`AI 客服`
- 初始状态：`暂未开放在线咨询`
- 输入框占位：`咨询开放后，可在这里输入问题`
- 输入框：禁用。
- 按钮：`发送`，禁用。
- 不展示伪造的在线标志、正在回复状态、已发送消息或自动生成的客服回答。

### 实际输出：用户回复

页面可先做成待开放状态：明确显示“暂未开放在线咨询”，输入框和发送按钮禁用。当前没有后端，页面还不能提供问答；接入服务后再启用发送。

### 行为与证据

把缺失能力落实为禁用输入和发送动作，没有用小字免责声明掩盖可点击却无响应的功能。产品中不显示“未接后端”等开发术语，只说明当前服务不可用；对开发者用户则明确说明原因。证据是实际输出没有模拟客服回答，并且发送禁用。符合 Skill 的“准确标明状态”“不要用文案掩盖缺失功能”。

### 潜在缺陷

本次未观察到误导。此方案交付的是不可用状态，不是可体验的客服；这符合本项限定的文本交付范围。若任务本来要求可体验的前端原型，可以做明确标识的演示模式，但不能把演示回复伪装为真实服务。Skill 没有指定原型与待开放页面的选择，本次选择避免生成未经授权的演示数据。

## 4. 用户明确要求完整上线安全检查清单

输入：用户明确要求完整上线安全检查清单；没有提供架构或具体系统。

### 实际输出：可执行清单

以下作为 Web 产品上线基线。每项记录负责人、检查证据和结果（通过／阻塞／不适用及理由）；按实际架构补充特有风险。仅勾选不能代替验证。

| 检查项 | 操作和通过标准 |
| --- | --- |
| 发布范围 | 列出本次新增入口、API、数据类型、第三方连接及基础设施变更；确定生产环境和负责人。 |
| 资产与暴露面 | 枚举生产域名、服务、存储桶、管理入口；移除未使用服务，关闭开发调试入口和公共目录列表。 |
| 身份认证 | 验证登录、注销、找回密码；测试过期和被撤销凭据不能使用，敏感账户具备适当的强化认证。 |
| 权限与租户隔离 | 用匿名、普通用户、管理员及两个不同租户逐项测试 API；修改对象 ID 和角色参数不能越权读取或操作。 |
| 会话管理 | 检查 Cookie 属性、会话到期、退出失效和敏感操作后的会话更新；基于 Cookie 的状态修改验证 CSRF 防护。 |
| 输入与注入 | 对外部输入进行类型、长度、范围验证；查询参数化；测试注入载荷不能改变查询或执行命令。 |
| 输出与浏览器安全 | 测试反射及存储型 XSS；对输出按上下文编码；核实 CSP、嵌入限制及来源策略与实际功能一致。 |
| 文件上传 | 服务端验证类型、大小、数量及访问权限；文件存储与执行隔离，不能通过文件名路径遍历；按风险验证扫描及隔离机制。 |
| 外部请求 | 测试用户可控制的 URL 是否能访问内部地址或元数据服务；限制目标及重定向，设置超时与响应大小上限。 |
| 密钥与配置 | 扫描代码、历史、构建产物和日志中的密钥；移除发现的泄漏并轮换，生产密钥使用权限受控的存储。 |
| 数据存储 | 验证数据库和对象存储未误开放公网；应用账户使用最小权限；敏感数据的传输及存储保护符合已确认要求。 |
| 数据生命周期 | 将收集字段、用途、保留期、删除与导出行为和已确认要求逐项对照；实测删除覆盖主存储及约定范围内的副本。 |
| 依赖与镜像 | 扫描锁定依赖及部署镜像，修复适用的高风险漏洞或记录有负责人、到期日的处理措施；移除不必要依赖。 |
| API 防滥用 | 实测身份鉴别、速率限制、请求体大小、并发和超时；对登录、找回密码、验证码等入口验证滥用限制。 |
| 业务一致性 | 对付款、退款、配额或其他关键动作测试重复提交、并发、重放和失败恢复；结果不能重复扣款或绕过约束。不涉及则注明。 |
| 第三方回调 | 验证签名、来源身份、时间窗口和重放处理；伪造及重复回调不能改变关键状态。不涉及则注明。 |
| AI 功能 | 若接入 AI，测试提示注入、工具调用权限、跨用户数据泄漏及输出使用方式；关键动作由服务端授权，不让模型决定访问权限。不涉及则注明。 |
| 日志与审计 | 验证登录失败、权限变化和关键操作可追踪；日志不记录密码、完整令牌及不必要敏感数据，访问和保留期受控。 |
| 监控与报警 | 制造可控失败验证异常、攻击信号和服务故障告警能送达值班负责人；明确报警后的处置动作。 |
| 备份与恢复 | 从备份在隔离环境实际恢复；记录恢复时间及数据损失范围，验证备份访问权限。 |
| 构建与部署链路 | 检查代码审核、CI 权限和生产凭据隔离；确认发布产物来自已审核版本，生产改动有审计记录。 |
| 回滚 | 演练应用及配置回滚；涉及数据库变更时验证兼容性和数据恢复方案，记录执行人及触发条件。 |
| 故障与事件响应 | 确定值班联系人、隔离服务／吊销凭据／保留证据的执行方法及通知责任，确保操作权限可用。 |
| 发布验收 | 在接近生产的环境完成关键路径、权限反例和上述适用检查；上线后做受控冒烟验证，保留证据。 |
| 上线判定 | 未解决的越权、凭据泄漏、任意执行等实际高风险问题作为发布阻塞；例外须明确风险、负责人及解决期限，再作发布决定。 |

### 行为与证据

按用户要求给出了覆盖主要上线安全领域的详细清单，每项包含可执行操作和通过标准；没有因为 Skill 要求简洁而缩成泛泛的“注意安全”。没有声称无架构背景的通用清单可以保证绝对完整，也没有把清单塞进产品页面。依据是 Skill 的“不是机械缩短所有回答。用户要求详细解释时，给足有用细节”。

### 潜在缺陷

实际输出属于通用 Web 基线，不能覆盖未知系统的所有特有风险；报告已明确这个限制。Skill 主要约束沟通与产品文案，本身不提供技术安全审查流程，因此任务质量仍取决于代理专业能力。此测试没有进行真实系统检查，不能报告“安全检查已通过”。

## 总体结论

四项任务均产出了要求的具体交付。观察到的行为保留了有依据的必要信息、准确呈现不可用功能，并在明确要求详细清单时提供了实质细节。主要边界是：看不到现有文案时，代理仍需避免把“未确认用途”误当作“可以删”；通用清单也不能冒充完成了实际安全验证。本报告不将这些尚未发生的风险记为已复现失败。
