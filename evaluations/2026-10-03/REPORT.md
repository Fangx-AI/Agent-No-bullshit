# 第一轮评估 · 2026-10-03

**观察到局部表达改善，也发现了真实功能问题。补充一条验收规则后，第二轮独立生成的页面通过了针对性复测。**

这是一轮探索性测试，不是性能排行榜，也不足以证明 Skill 在所有任务中稳定有效。

## 怎么测

两个独立 Agent 接收相同的五项任务：本地图片压缩工具、永久/可撤销删除文案、开发交付回复、详细压缩原理说明、尚未接入支付的订阅页文案。一组读取原版 Skill，另一组不读取；它们不能查看彼此的结果。另一个 Agent 测试四项边界情景，并对文本作独立评审。评审知道组别，不属于盲审。

发现功能问题后，只补充一条规则，交给新的 Agent 独立完成同一图片压缩任务，没有向生成者提供第一轮失败答案。随后由测试者运行针对性回归。

所有 Agent 使用当前会话继承的模型配置。每种条件只有一次生成，没有跨模型、多次重复或统计显著性分析。

## 实际结果

| 场景 | 观察 |
| --- | --- |
| 开发交付 | 两组都保留构建通过、真机未测。带 Skill 的版本减少同一限制的重复解释。 |
| 订阅页 | 两组都保留 ¥29/月、自动续费、可随时取消和暂不能开通。带 Skill 的版本减少重复的不可用说明。 |
| 删除文案 | 两组都保留不可恢复后果和撤销入口。带 Skill 的可撤销按钮没有写数量，也未给撤销成功提示；缺少完整页面上下文，不能判定实际误删风险，也不能声称更好。 |
| 详细解释 | 两组都有原理及可执行故障处理。带 Skill 的版本没有机械压短，但不是每项细节都比基线全面。 |
| 普通产品界面 | 两组原本都没有大量泛泛免责声明或额外协议弹窗，因此本轮没有证明 Skill 对这类内容的减少效果。 |

开发交付的实际文本：

**不带 Skill（73 字，含标点）**

> 修改已完成，构建已运行并通过。尚未做真机测试，因此目前只能确认构建成功，无法确认真机上的运行表现。上线前还需要验证目标设备上的核心操作和显示效果。

**带原版 Skill（33 字，含标点）**

> 已完成修改，构建通过。尚未进行真机测试，真机上的运行效果仍需验证。

字数仅描述该例；评价依据是必要事实是否保留、重复解释是否减少。

## 找到并处理的问题

原版 Skill 生成的压缩页有两类状态错误：

- 完成后修改质量或输出格式，下载入口隐藏了，但旧体积与比例仍显示。
- 编码期间修改质量或格式，旧异步回调仍可能显示与当前输入不一致的下载结果。

第一类经实际浏览器操作复现；第二类用延迟 Canvas 回调的 Node VM 测试复现。旧版测试结果保留了失败，不将脚本正常退出误称为全部通过。

Skill 新增规则：

> 做产品仍需验证主流程，以及会影响结果的输入变更、处理中、失败和重试状态；界面显示的结果必须对应当前输入。用实际行为判断完成度，不能把文案短、代码能解析或构建通过当成功能可用。

没有把某个图片工具的代码修法写进通用 Skill。

第二轮独立生成的页面改为自动重新压缩，并对输入版本作校验。五项针对性逻辑测试均通过：处理中改质量、完成后改质量、切换文件、编码失败后重试、读取失败后重试。实际浏览器也验证了选图、压缩、质量变更、损坏文件与重新选图恢复。

第二版没有 PNG 输出选项，因此原版“切换输出格式”场景不适用，不能将它计作通过。二次生成存在随机性，不能仅凭这一次成功把改善全部归因于新增规则。

## 必要信息会不会被删

四项边界文本任务中，实际输出均保留了需要的信息：

- 已明确要求接受的服务协议，仍保留接受入口。
- 已确认的服务器上传及保留 30 天，仍完整呈现。
- 没有后端的客服页，显示待开放并禁用发送，没有伪造服务。
- 用户明确要求详细上线安全清单，仍提供可执行细项。

这是文本情景测试，不代表完成真实系统安全检查。现有文案用途未知时，仍需先辨别用途；“未确认必要”不能直接当作“可以删除”。

## 当前判断

Skill 对本次开发回复与订阅文案有局部帮助，必要信息和详细解释总体保留。它不能保证生成代码质量，也不能凭一轮样本证明能稳定抑制泛泛合规文案。

下一轮最值得增加的证据，是有明确多余文案的真实产品修改、多次重复对照，以及带完整上下文的批量删除/撤销闭环；不为尚未复现的问题继续堆规则。
