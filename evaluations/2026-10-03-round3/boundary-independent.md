## 3：明确要求详细解释

交付回复：这四种状态分别决定结果是否属于当前输入、错误是否能被修正、复制是否实际完成，以及清空是否彻底生效。格式化工具只有在这些情况下都能正确反馈，用户才可以相信它展示和复制的内容。下面给出实现思路、具体错误例子和验证方法。

### 输入改变：防止旧结果被当成当前结果

用户格式化后继续编辑输入，原来的结果就不再对应当前内容。若结果区仍显示旧结果，复制按钮也继续可用，用户可能把旧数据复制出去。即使采用自动格式化，也会出现等待解析或旧任务较晚完成的时间窗口。

实现思路：

- 每次输入改变，增加输入版本号，并立即让上一次结果失效。清除旧错误，禁用复制。
- 手动格式化时显示“输入已修改，请重新格式化”；自动格式化时显示“正在格式化…”。选用与工具实际行为一致的一种反馈。
- 每次格式化记录输入快照及版本号。结果或错误返回时，仅在版本号仍与当前输入一致时更新界面。
- 复制使用已提交且属于当前版本的结果，不能读取过期结果。

具体错误例子：先格式化 `{"count":1}`，随后把输入改成 `{"count":2}`。错误行为是结果和复制内容仍为 `"count": 1`。另一个错误是用户快速输入 A、B 后，A 的解析结果较晚返回并覆盖 B 的结果。

验证方法：先得到 `count` 为 1 的结果，再将输入改为 2。在重新格式化完成前，检查复制按钮不可用；完成后，检查展示和复制内容都为 2。若解析通过异步任务执行，用可控制的延迟让 A 晚于 B 返回，确认 A 不能覆盖 B；再把 B 改成非法 JSON，确认旧的有效结果不能重新出现。

可见文案（手动格式化方案）：

- 输入改变后：`输入已修改，请重新格式化。`
- 运行中：`正在格式化…`

### 格式错误：指出可修正的输入问题

JSON 格式化应保持数据含义。非法 JSON 无法直接生成可信结果；如果静默补逗号、改引号或忽略解析错误，可能把用户原本的数据改成另一份数据。只写“失败”也无法帮助用户找到问题。

实现思路：

- 使用 JSON 解析器校验输入，再格式化解析结果。解析失败时清除结果并禁用复制。
- 把空输入作为独立状态处理，提示用户输入内容，不用语法错误吓阻用户。
- 使用解析器提供的位置定位错误；只有可以可靠取得位置时才显示行、列。不能从不稳定的错误文本猜出位置。
- 在支持结构化错误分类时提供具体原因；否则给出准确的通用错误提示，并定位可确认的位置。不要擅自修改输入。

具体错误例子：`{"name":"Ada",}` 的结尾多了逗号；`{'name':'Ada'}` 使用了单引号；`{"a":1 "b":2}` 在两个属性之间缺少逗号。这三种输入都不能显示格式化成功，也不能继续复制之前的结果。

验证方法：分别输入上述三种错误，检查出现错误、结果失效、复制不可用。把它们改为 `{"name":"Ada"}`、`{"name":"Ada"}`、`{"a":1,"b":2}`，再次格式化，检查错误消失且结果可复制。补充测试空输入和仅有空白的输入，确认提示为输入要求；测试多行错误，确认显示的位置确实指向当前输入。

可见文案：

- 空输入：`请输入 JSON。`
- 通用解析错误：`JSON 格式有误，请检查输入。`
- 已可靠定位时：`第 {行} 行，第 {列} 列：JSON 格式有误。`
- 已确认尾逗号错误时：`请删除最后一个字段后的逗号。`

开发备注：通用提示、定位提示和具体原因按解析能力选用；不要同时叠加重复说明，也不要在没有定位能力时展示占位行列。

### 复制受限：把格式化完成与复制完成分别反馈

格式化成功只证明结果已生成。浏览器可能限制剪贴板访问，用户也可能拒绝权限；复制操作可能因此失败。点击按钮后立即显示“已复制”，会让用户误以为剪贴板已经更新。

实现思路：

- 在用户点击“复制”时调用剪贴板 API，等待操作实际成功后再显示“已复制”。
- API 不可用或调用被拒绝时保留当前结果，显示手动复制办法。不能把复制失败当成 JSON 输入错误。
- 复制过程中锁定本次复制的结果快照。若此时用户改了输入，完成反馈应明确指向本次复制的结果；也可以在输入改变时取消已经失效的页面反馈，避免暗示新输入已经被复制。
- 结果区保持可选中，方便用户用键盘或系统菜单复制。

具体错误例子：`{"name":"Ada"}` 已格式化成功，但 `navigator.clipboard.writeText` 被拒绝并抛出 `NotAllowedError`。错误行为是仍显示“已复制”，或把结果清空并提示“JSON 格式错误”。正确行为是保留结果，并指导用户手动复制。

验证方法：通过测试替身让剪贴板调用返回失败，检查页面没有显示“已复制”，结果仍可选中，提示给出手动复制动作。让剪贴板调用返回成功，检查只有成功后才出现“已复制”，并核对复制内容等于当前有效结果。再模拟 API 缺失以及点击复制后立即编辑输入的情况，确认不会把旧结果的复制成功误标为新输入的复制成功。

可见文案：

- 按钮：`复制`
- 成功：`已复制`
- 受限或失败：`无法自动复制，请选中结果后手动复制。`

### 清空：让输入、结果和状态一起回到空白

清空表达的是用户要移除当前内容并开始下一次输入。如果只清空输入，结果区、错误或“已复制”反馈仍留着，页面就会同时展示不相容的状态。尚未完成的格式化任务也可能在清空后把旧结果填回来。

实现思路：

- 在一次状态更新中清空输入、结果、解析错误和复制反馈，并禁用复制。
- 增加输入版本号，使清空前的异步格式化结果失效。可以取消的任务同时取消，但仍用版本检查防止迟到结果回填。
- 清空后将焦点放回输入框，方便用户继续输入。普通工具的可编辑输入清空无需额外确认步骤。

具体错误例子：输入 `{"count":1}` 并格式化成功，点击“清空”后输入为空，但输出仍显示 `"count": 1`，复制按钮仍可用。另一个例子是清空发生在格式化过程中，任务完成后旧输出再次出现。

验证方法：分别在格式化成功、解析失败、复制成功、格式化处理中点击“清空”。每次检查输入和结果为空、错误与复制反馈消失、复制不可用、焦点回到输入框。等待清空前的异步任务完成，确认旧内容不会回来；输入新的合法 JSON，确认下一轮格式化和复制可以正常进行。

可见文案：

- 按钮：`清空`
- 空输入框提示：`输入 JSON`

开发备注：以上为实现与验收方案，本次未修改工具或执行浏览器验证；各状态的可见文案需与选用的实际实现一致。

## 5：结果未知

交付回复：使用以下超时提示，并让用户刷新列表核对服务器的当前状态。提示不判断恢复了多少条。

可见文案：

- 提示：`撤销请求超时，恢复结果尚未确认。请刷新列表查看当前资料状态。`
- 按钮：`刷新列表`

开发备注：“刷新列表”应重新读取服务器状态。若刷新也失败，继续保留恢复结果未知的状态。服务器没有提供恢复数量，不能显示“全部未恢复”“已恢复 0 条”或推断仍需恢复的条数；不要自动重发撤销请求。若要提供重试，应先确认服务端支持重复撤销，并针对已核实的未恢复资料执行。
