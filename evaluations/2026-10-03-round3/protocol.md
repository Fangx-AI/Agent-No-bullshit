# 第三轮优化协议

目的：使用没有要求删废话的普通产品需求，评估基线、现有 Skill 与候选机制的实际产物。不得将题干要求的演示状态、真实撤销期限或具体错误指引记为废话。

同一固定 tasks.md 包含三个真实可交付产品任务。独立生成者只读任务和其指定条件的 Skill，不读其他输出。保留旧产物与候选，不按结果选择性丢弃失败。

人工/独立评审对界面实际字符串分类：
- 完成任务必需的控件/标签；
- 当前状态、真实限制/后果、恢复办法；
- 用户明确请求的说明；
- 重复描述已有控件、未经要求的功能宣传/教程、对开发者的实现备注、无具体依据的合规说教。

只将最后一类作为有证据的删减对象。短句不自动合格，长解释不自动失败。示例状态明确、真实功能不退化是前置要求。

基线、当前版和候选版都接受独立评审。在完整评审结论出来之前，另安排同任务的新独立候选生成，同时补一组当前版重复生成，减少对单次产物的依赖。最终条件数量为无 Skill 1 组、当前版 2 组、候选版 2 组；每组均完整保留三个页面。记录小样本限制，不伪造稳定效果或统计显著性。

条件通过直接要求读取指定 Skill 显式加载。本轮未评估自动发现和触发率。评审隐藏条件名称，但只属于小样本文案评审，不是严格双盲研究。品牌、情绪和装饰文字单列为可选设计文案；不和重复操作反馈或合规冗余混计。

首候选的第二次生成暴露了撤销后果缺失，第一组预约的演示后果也弱于对照。因此未直接采用初候选；补充“标签和倒计时不能替代关键后果”的规则后，另做两组 B/C 独立生成。B/C 是实际暴露问题的题目；最终版未另行重新生成 A，报告需明确这一范围。并用五题复测真实上传事实、未知协议正文、明确要求详细解释、永久删除前确认和结果未知的失败提示。

这一轮补充后，两组 B 的操作边界与 C 的删除前后果均明确，但两组 C 仍出现重复的可见成功播报。因此继续将去重落实到“复用已有操作结果区，不叠加同内容 toast/状态段，并保留必要读屏播报”的实现选择。随后再独立生成两份 C，作为最后修订的定向复测；不将较早 B/C 样本标成最后修订生成的产物。最终版本的 A/B 未另行生成，不作这项主张。

反馈机制版的两份 C 通过后，五题边界答复的标题暴露出 Skill 示例的矛盾：结果未知却写“撤销未成功”。修正为请求超时与结果尚未确认，并补充标题/正文一致性。最后以未知结果和已确认 5 条均未恢复作两个对照场景，各做两次独立生成及复核。最后修订只验证这两种结果文案，没有再次生成 HTML；报告保留各版本及对应的准确验证范围。

浏览器实际验证主要操作路径与易出错状态，只通过 cua_repl 操作。纯逻辑或语法工具不能冒充浏览器/磁盘下载验证。修改 Skill 只依据观察到的行为或明确标记为待测的假设；发布前须复测并如实报告未解决项。
