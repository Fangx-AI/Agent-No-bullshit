## 3：明确要求详细解释

### 实际交付回复

JSON 格式化工具要保证：结果对应当前输入，错误能够定位和修正，复制按钮反映真实执行结果，清空能把工具恢复到可继续使用的状态。这四种状态各自解决一个实际问题，处理好之后，用户才能判断眼前的结果是否可用。

下面采用一个明确的交互方案：用户修改输入后，点击“格式化”生成结果；输入一旦改变，旧结果立即失效；只有当前输入格式化成功，才允许复制。

#### 一、输入改变

**为什么需要处理**

格式化结果属于生成它的那一份输入。输入改了，旧结果就不能继续被当作当前结果使用。例如，用户将 `{"count":1}` 改成 `{"count":2}`，右侧仍显示 `1`，点击复制就会拿到已经过时的内容。即使两份输入都是合法 JSON，这仍是功能错误。

**实现思路**

监听输入变化，每次变化增加一个输入版本号，同时清除旧结果和旧错误，禁用复制。非空输入允许点击“格式化”；空白输入禁用格式化。格式化时保存当时的输入和版本号，通过 `JSON.parse` 解析，再用 `JSON.stringify(value, null, 2)` 生成结果。

如果格式化通过异步任务执行，返回时必须比较版本号。只有返回结果的版本与当前输入版本相同，才能更新界面。旧任务的成功结果和错误都应丢弃；否则用户修改输入后，旧任务仍可能把过时的内容写回来。复制处理函数也要检查结果版本，而不能只依赖按钮外观。

**具体错误例子**

输入 A 为 `{"count":1}`，开始格式化。任务尚未完成时，输入改成 B：`{"count":2}`。A 的任务稍后完成，覆盖了 B 的界面，复制出来仍为 `1`。

**可操作的验证方法**

1. 输入 A 并格式化，确认结果为 `1`，复制可用。
2. 改为 B，确认旧结果被清除，复制立即不可用。
3. 格式化 B，确认显示和复制内容都为 `2`。
4. 如果使用异步任务，在测试中延迟 A 的返回，然后先完成 B，再返回 A。确认界面仍显示 B，旧任务的错误也不会覆盖 B。

#### 二、格式错误

**为什么需要处理**

格式化只能重新排列合法 JSON，不能凭空决定错误输入应该表达什么。不处理解析失败，可能出现按钮没有反馈、程序异常，或仍显示上一份合法结果。用户需要知道输入哪里不符合 JSON 语法，并能修改后再次格式化。

**实现思路**

捕获 `JSON.parse` 的解析异常，清空结果并禁用复制，在输入区显示错误。解析器如果提供可靠的字符位置，可根据换行计算行号和列号，并定位对应位置；如果没有可靠位置，就只显示“JSON 格式错误，请检查引号、逗号和括号”，不能编造行列号。

输入修改后清除过期错误，下一次点击“格式化”重新解析。不要通过删除逗号、替换引号等自动修复来猜测原意。合法 JSON 不只包括对象和数组，`null`、`true`、数字和字符串也应按解析结果处理。

**具体错误例子**

- `{"name":"Lin",}`：对象最后一项后多了一个逗号。
- `{'name':'Lin'}`：JSON 字符串及属性名需要使用双引号。
- `{"name":"Lin"`：缺少闭合的大括号。

**可操作的验证方法**

1. 逐一输入上述三种错误，点击“格式化”，确认显示错误、没有结果、复制不可用。
2. 将第一种输入修正为 `{"name":"Lin"}`，再次格式化，确认错误消失并出现正确结果。
3. 先格式化合法内容，再换成错误内容，确认不会留下之前的成功结果。
4. 如果显示行列号，用多行错误输入验证定位确实指向解析器报告的位置；无法取得位置时，确认界面没有虚假的位置提示。
5. 分别输入 `null`、`true` 和 `[1,2]`，确认工具接受这些合法 JSON 值。

#### 三、复制受限

**为什么需要处理**

存在格式化结果，并不表示浏览器一定允许写入剪贴板。复制调用可能因权限或环境限制而失败。用户点击后若仍看到“已复制”，就会误以为剪贴板里已有新内容，随后粘贴出来的可能是旧内容。

**实现思路**

在用户点击复制时，先检查结果是否属于当前输入，然后调用剪贴板写入方法，等待调用成功后才显示“已复制”。调用被拒绝或接口不可用时，保留结果，显示“复制失败，请选中结果后手动复制”。结果区需要允许选中文本；如果使用只读文本框，也应支持键盘选择和复制。

复制反馈放在结果区的一处状态位置。需要读屏播报时让该状态可播报，不再新增一个显示相同内容的 toast。输入变化或清空时，同时清除旧的复制状态；异步复制返回的反馈也需检查版本，避免在新输入下显示旧操作的“已复制”。

**具体错误例子**

将剪贴板写入调用模拟为拒绝并返回 `NotAllowedError`。如果代码在等待结果之前就显示“已复制”，复制失败后仍会产生错误的成功反馈。

**可操作的验证方法**

1. 格式化一份合法 JSON，复制到可检查内容的文本框，确认粘贴内容与当前结果一致。
2. 在测试中让剪贴板写入调用拒绝，确认只出现失败反馈，结果仍可选中并手动复制。
3. 模拟剪贴板接口不存在，确认仍能给出失败反馈，而不会抛出未处理异常。
4. 延迟复制调用的返回，期间修改输入或清空，确认旧调用完成后不会在当前状态显示“已复制”。

#### 四、清空

**为什么需要处理**

用户清空是为了开始下一次操作。如果只清空输入，结果、错误或“已复制”还留在页面上，工具就会同时呈现互相矛盾的状态。未完成的异步任务还可能在清空之后重新填回旧内容。

**实现思路**

清空时统一重置输入、结果、解析错误和复制反馈，增加输入版本号，使旧任务失效。存在可取消任务时一并取消；无论能否取消，都必须在返回时检查版本。随后禁用格式化和复制，将焦点放回输入框，方便继续输入。这个可重新输入的动作无需新增确认弹窗。

**具体错误例子**

用户点击“清空”后，输入为空，结果区却仍显示 `{"count":1}`，复制按钮也仍可用；或者清空后，尚未完成的格式化任务返回并重新显示这份结果。

**可操作的验证方法**

1. 在成功结果状态点击“清空”，确认输入、结果及复制反馈全部消失，两个相关操作按钮不可用。
2. 在格式错误状态点击“清空”，确认错误也消失。
3. 在异步格式化处理中点击“清空”，等待旧任务返回，确认页面仍为空。
4. 清空后输入新的合法 JSON，再格式化和复制，确认完整流程仍可使用，焦点已回到输入框。

以上是实现方案和验收方法；本题没有提供可执行的工具代码，因此未报告实际运行测试结果。

### 可直接展示的界面文字

- 输入标签：`JSON 输入`
- 按钮：`格式化`、`复制`、`清空`
- 结果标签：`格式化结果`
- 异步处理中：`正在格式化…`
- 无可靠错误位置时：`JSON 格式错误，请检查引号、逗号和括号。`
- 复制成功：`已复制`

### 开发备注

“正在格式化…”仅在实际存在异步等待时展示。错误有可靠位置时，使用实际行列位置生成对应提示。各状态按上面的条件切换，不同时展示彼此过期的反馈。
