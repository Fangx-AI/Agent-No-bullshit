# 第三轮：把去重变成具体做法

本轮验证到一个局部改善：两份新生成的资料页都将删除结果、倒计时和撤销入口放在一个反馈区，减少重复的可见成功提示，同时在删除前明确“30 秒后无法恢复”。真实浏览器中的新增、保存、搜索、删除、撤销和到期路径通过。

过程中也发现并修正了两类问题：删减会遗漏关键后果；“撤销未成功”这一示例会把超时未知结果误写成失败。失败样本全部保留。没有观察到各组普遍堆叠合规长文，因此本轮没有证明通用的合规废话减少效果。

## 怎么测试

[固定任务](tasks.md)没有要求“简洁”或“删废话”：直接交付 JSON 工具、播客预约原型和课程资料页。无 Skill 1 组、旧版 2 组、首候选 2 组，共 15 个完整原型；后续定向修订生成 4 个 B/C 原型及 2 个 C 原型，总计 21 个。

生成者使用独立上下文，不读取其他产物。评审隐藏条件名称，按实际可见文字及状态字符串判断；品牌和情绪句单列，必要提示、具体错误指引、不同用途的反馈不当作废话。Skill 显式加载；未评估自动触发率。完整流程见[协议](protocol.md)。

## 发现与修订

| 阶段 | 具体结果 | 处理 |
| :--- | :--- | :--- |
| 旧版两组 | 同一次删除同时出现成功状态段和撤销卡 | 去重需要落实到反馈区域 |
| 首候选两组 | 删除反馈不再重复，但其中一组缺少明确的到期后果；预约的演示后果也减弱 | 标签、倒计时不能代替关键后果 |
| 补后果版两组 | 删除前及提交附近的后果均明确，但两组 C 又出现重复成功提示 | 明确复用已有结果区，不叠加同内容 toast 或状态段 |
| 反馈机制版两组 C | 一处可见删除结果与撤销入口，删除前后果保留；另有不可见读屏播报 | 文案审查与浏览器主流程通过 |
| 边界题 | 正文保留结果未知，但标题写“撤销未成功” | 修正 Skill 中误导示例，要求标题与正文一致 |
| 最后两组结果文案 | 未知结果写超时与尚未确认；已确认 5 条未恢复则准确陈述失败并提供重试 | 两组复核通过 |

“同一事实只说一次”仍可能被模型忽略。更具体的规则是：**已有操作区承载结果与下一步，就复用这一处反馈；去重针对重复可见文字，保留有不同用途的反馈。** 读屏播报可以复用该区或采用不可见播报。

第一组[独立评审](blind-review-first.md)、[重复样本评审](blind-review-repeat.md)、最后的[文案及边界评审](final-review.md)和[结果文案复核](unknown-review.md)均保留原句。最后评审也明确记录了失败标题，随后才进行修订。

## 必要信息保留了吗

五题[边界测试](boundary-tasks.md)覆盖上传前的服务器、保存 30 天、JPG/PNG、10 MB；未知协议正文与已要求保留的勾选；明确要求详细解释；永久删除确认前的后果；撤销超时的未知结果。

前四题通过。详细解释仍对四种状态逐一给出实现思路、错误例子和验证方法。第五题的误导标题经过修订后，用[两个对照场景](unknown-cases.md)重新生成：

| 条件 | 两次独立答复 | 核对结果 |
| :--- | :--- | :--- |
| 超时，恢复结果未知 | “撤销请求超时” / “恢复结果尚未确认” / “刷新列表” | 没有将未知写成失败或恢复数量 |
| 已确认这 5 条均未恢复 | “撤销失败” / “这 5 条资料均未恢复” / “重试撤销” | 保留已知结果及允许的下一步 |

[答复一](unknown-one.md)、[答复二](unknown-two.md)与[独立复核](unknown-review.md)可直接对照。最后修订只涉及未知结果及标题一致性，没有重新生成整套 HTML；资料页的两次验证对应上一份反馈机制版。

## 实际验证范围

[浏览器记录](browser-log.md)区分真实操作、过程观察与冻结文件复查。主 Agent 使用 cua_repl；不同条件使用不同 localhost 端口隔离存储。

- 首组无 Skill、旧版、首候选：检查主要操作路径，包括 JSON 的实际剪贴板内容，以及资料页真实等待 30 秒后的状态。
- 补后果版：两份预约实际提交生成预览；资料页操作用于观察重复反馈，没有作为最后版本验收。
- 反馈机制版：两份冻结 C 文件均检查新增、重载保存、搜索、选择删除和期限内撤销；真实经过 30 秒后不可撤销。第一份还重载确认已到期资料没有回来。

读屏相关检查确认了隐藏播报标记和 CSS，不等于实际屏幕阅读器验收。未穷尽浏览器兼容性、存储故障界面、跨标签页并发或全部输入组合。没有预约服务、真实邮件或支付调用。

纯逻辑检查的范围各不相同，不把断言数量当作条件优劣分数。脚本使用真实产物中的逻辑，部分检查采用内存 DOM 或存储替身。可在仓库根目录复跑，例如：

```bash
node evaluations/2026-10-03-round3/baseline/verify.cjs
node evaluations/2026-10-03-round3/current-logic-check.cjs
node evaluations/2026-10-03-round3/candidate-run/verify.cjs
node evaluations/2026-10-03-round3/feedback-one/verify-task-c.cjs
```

归档 `check-final-one.cjs` 和 `final-two-check.js` 时仅将本机绝对路径改为仓库相对路径，并重新运行通过。
