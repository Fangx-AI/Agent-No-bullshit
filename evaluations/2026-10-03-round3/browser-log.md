# 统一浏览器验证记录

2026-10-03，主 Agent 全部通过 cua_repl 操作真实页面。不同条件使用不同 localhost 端口，避免 localStorage 互相污染。仅使用虚构的测试资料和 test@example.com。

## 无 Skill 样本

- A：实际格式化 `{"a":1}`，复制后读取浏览器剪贴板，内容与格式化输出一致。改为不完整 JSON 后点击格式化，旧结果清空、复制禁用，并显示继续修改的提示。错误还含浏览器英文诊断。修复后可重新格式化，再清空两栏并禁用复制。
- B：选择可用时段、姓名与邮箱后提交，页面显示对应日期、时段和联系方式，并明确属于演示预约、没有创建真实预约或发送邮件。
- C：新增两项资料，重载后均存在；搜索只显示匹配项。勾选匹配项删除后立即撤销，资料恢复；清空搜索显示两项。再删除两项，实际经过 30 秒后撤销入口消失、资料列表仍为空，显示对应两项无法恢复。

## 候选版第一组

- A：实际格式化 `{"a":1}`，复制后读取剪贴板，内容一致。更改为不完整 JSON 后，旧输出清空、复制禁用，并提供检查双引号、逗号和括号的继续操作提示。修正后格式化成功；清空恢复等待输入状态。

- C：新增、重载保存、搜索、删除后立即撤销均成功。生成 Agent 最后修改 C 的缺失批次文案、到期读取与焦点处理后，主 Agent 重新打开最终文件，复查新增、勾选、删除和恢复。再次删除并实际等待 30 秒后，撤销入口消失、列表仍为空，显示这 1 条资料无法恢复。先前版本的测试只作过程记录，最终版本的复查用于验收。

## 补后果版（final-one / final-two，中间版本）

两份 B 均在提交附近明确“只生成预约预览，不会实际预约”。选择可用时段，填写虚构姓名与邮箱后提交，均显示与输入相符的预约预览。

C 的新增、重载、搜索、选择删除用于观察状态文字：两份均同时显示独立成功状态段与撤销卡，确认笼统去重规则仍不足。这些中间文件没有作为最后修订的浏览器验收依据。

## 反馈机制版（feedback-one / feedback-two）

两份生成文件冻结后均重新打开核对，并通过新增、重载保存、搜索、勾选删除和期限内撤销：

- 第一份：新增两项“冻结验证”资料，重载仍存在；搜索甲、勾选删除，只有一处可见结果卡，撤销后甲重新出现。再搜索并全选两项删除，真实经过 30 秒后卡片改为这两项已到期、无法恢复，撤销按钮消失。重载后两项没有回来，未删除的其他资料仍在。
- 第二份：新增两项“最终验证”资料，重载仍存在；搜索甲并删除后只有一个可见删除结果区。实际经过 30 秒后该项变为到期提示，没有撤销入口。另搜索乙、删除并立即撤销，乙重新出现在列表中。不可见 announcer 的播报不作为重复可见文字计数。

两份都在删除前明确“删除后可在 30 秒内撤销，超时无法恢复”。独立静态评审确认隐藏播报的 CSS；没有运行实际屏幕阅读器。期限检查没有用假时钟代替真实等待；精确的 29999/30000 毫秒边界另属纯逻辑检查。

这是具体操作路径的验收，不代表穷尽浏览器兼容性、存储故障、跨标签页并发或所有输入组合。
